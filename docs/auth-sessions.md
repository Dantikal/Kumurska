# Сессии и токены: контракт для клиента (US-25)

Разблокирует US-22 (Face ID), US-05 и US-05.1.

## X-Device-Id

UUID устройства. Приложение генерирует его **один раз** при первом запуске и хранит
локально (Keychain / EncryptedSharedPreferences). Не меняется между запусками и при выходе.

Заголовок обязателен для:

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/otp/verify`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`

Нет заголовка или значение не UUID → `422 VALIDATION_ERROR`.

На одно устройство приходится одна сессия: новый вход с тем же `X-Device-Id` завершает
прежнюю сессию этого устройства. Сессии на других устройствах не затрагиваются.

## Токены

| | Срок | Где хранить |
|---|---|---|
| `access_token` | 15 минут (`expires_in`, секунды) | в памяти или в защищённом хранилище |
| `refresh_token` | 30 дней | только в защищённом хранилище |

Формат ответа у `login`, `otp/verify` и `refresh` один и тот же:

```json
{ "access_token": "...", "refresh_token": "...", "token_type": "bearer", "expires_in": 900 }
```

## POST /api/v1/auth/refresh

```http
POST /api/v1/auth/refresh
X-Device-Id: 6f1c2b0e-4f1a-4c39-9a57-0b8f3d1e2a11
Content-Type: application/json

{ "refresh_token": "..." }
```

- `200`: новая пара. **Сразу сохраните новый refresh_token**, старый больше не действует.
- `401 SESSION_EXPIRED`: сессия завершена.
- `403 USER_BLOCKED`: аккаунт заблокирован или удалён.

Refresh-токен **одноразовый**. Если отправить уже обменянный токен ещё раз, сервер
сочтёт это кражей и завершит всю сессию (`SESSION_EXPIRED`).

**Обязательно:** не больше одного refresh одновременно. Параллельные запросы к API,
получившие `401 NOT_AUTHENTICATED`, ждут результата одного общего refresh, а не
запускают свой. Мягкого окна для повтора на сервере нет. Если сеть оборвалась
во время refresh и ответа не было, повтор со старым токеном вернёт
`SESSION_EXPIRED`, и пользователю придётся войти заново.

## POST /api/v1/auth/logout

```http
POST /api/v1/auth/logout
Authorization: Bearer <access_token>
```

- `204` без тела. Повторный вызов тоже `204`.
- `401 NOT_AUTHENTICATED`, если access-токена нет, он неверный или истёк.
  Для выхода это не ошибка: всё равно очистите токены локально.

После выхода access и refresh этой сессии перестают приниматься сразу.

## Как клиенту реагировать на ошибки

| Код | HTTP | Действие клиента |
|---|---|---|
| `NOT_AUTHENTICATED` | 401 | один раз выполнить refresh и повторить запрос; если refresh не удался, перейти на приветствие |
| `SESSION_EXPIRED` | 401 | очистить токены и показать экран приветствия, refresh не пробовать |
| `USER_BLOCKED` | 403 | очистить токены и показать сообщение о блокировке |

`SESSION_EXPIRED` возвращают и обычные защищённые методы (например, `/users/me`),
если сессию отозвали: выход на этом устройстве, повторный вход с него же или
обнаружение кражи токена.
