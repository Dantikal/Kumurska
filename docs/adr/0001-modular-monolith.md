# ADR-0001: Модульный монолит

Статус: принято

## Контекст

Операции лояльности (покупка, списание, начисление, пересчёт уровня) должны
выполняться атомарно. Команда небольшая, продукт находится на старте.

## Решение

Основной бэкенд строится как модульный монолит с одной базой PostgreSQL.
Интеграция с 1С выносится в отдельный сервис, потому что внешняя система не
должна влиять на доступность основного API.

## Последствия

- Операции лояльности выполняются в обычных транзакциях БД.
- Деплой и локальная разработка остаются простыми.
- Границы модулей нужно соблюдать через соглашения и код-ревью.
